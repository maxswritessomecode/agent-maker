# Review Checklist

Use this when the user is deciding whether to keep, revise, split, merge, or discard an agent proposal.

## Keep

Recommend keeping the proposal when:

- the user recognizes the work pattern
- the agent can produce a useful draft without action permissions
- approved sources are enough for the first version
- the output has a clear folder or destination
- the blocked actions are acceptable

## Revise

Recommend revising when:

- evidence is real but the agent name or mission is off
- one source is noisy or should be removed
- the output format needs a template
- confidence is lower than the user wants
- boundaries need to be stricter

## Split

Recommend splitting when:

- one proposal mixes two jobs, such as status updates and meeting follow-ups
- different sources or permissions are needed
- one part is low risk and another part is sensitive

## Merge

Recommend merging when:

- two proposals use the same sources
- the outputs are reviewed together
- the user would naturally invoke them as one assistant

## Discard

Recommend discarding when:

- evidence is thin
- the task is not painful or frequent
- the work requires sensitive judgment
- the agent would need autonomous source-system changes
- the proposal drifts into monitoring, HR, legal, medical, financial, eligibility, or regulated decisions
